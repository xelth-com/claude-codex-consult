## Framing challenges (before Q1–Q5)

Options the brief does not list:

1. **Stratify instead of blend.** Show the table per judge tier (frontier / other / legacy-unknown) rather than one weighted column. This directly answers the operator's fear (a DeepSeek coordinator's 100% marks lifting Gemini) without inventing coefficients, and old events simply land in the legacy stratum.
2. **Distributions, not ranks.** Every column is confounded: task mix, selection (hard tasks go to strong reviewers), coordinator self-preference. A single combined score invites the encoding failure F02-1 names. Per-purpose tables with Wilson intervals and no global ordering are a real alternative.
3. **Consent-based identity (Q4).** A client opt-in (`telemetry_model_public = true`) lets an installation send its raw id — explicit consent replaces pattern-guessing.
4. **Inter-rater reliability (Q2).** Weight a judge by its agreement with the maintainer's own marks on overlapping consultations — measurable locally, no external table, no circularity.

To choose between blend and stratify I would need to know the consumer's actual decision (pick one reviewer? tune a roster?) and whether the maintainer accepts stratified display as satisfying ask #3.

## Q1. Ranking
Shrunken useful-rate: `p = (useful + 0.5·partial + k·m) / (n + 2k)` with m the global mean, k≈10 (a Beta prior; Wilson lower bound is the defensible alternative). Never give findings/blocker counts positive ranking weight (F02-1) — show them as columns; use blockers only as a tiebreak. Minimum n (~5) for top-10 eligibility; always display n. Paging keys on global rank only — rank-within-vendor re-orders rows between pages. Offer a vendor *filter* instead (unlisted option).

## Q2. Judge coefficients
The hand-kept tier table versioned with the site is the only listed option without a structural defect: LMArena/OpenRouter measure chat preference, not review judgment, and drift under a changing id mapping; the bridge's own table is circular and creates a feedback loop — weights change the ranking that sets the weights (finding #1). A weighted rate reads as "weighted useful share" shown beside raw counts. Old events get no judge: do not silently weight them 1.0; place them in the legacy stratum — the September marks are known out of band to be frontier judges, so a one-time documented legacy weight is defensible. Consider reliability weights (option 4 above) as the principled middle path.

## Q3. Judge field
Shape is right, provenance as proposed is wrong: copying the ledger's coordinator attributes the mark to the consult-time coordinator, not the rating actor (F02-3 — confirmed: `-Rate` builds the event from the ledger entry at codex-findings.ps1:475). Resolve coordinator identity at *rating* time and serialize `{provider, model, host}` through the closed-list path. Do not reuse `Get-TelemetryVendor` blindly: the coordinator record has no `provider_config` (codex-consult-common.ps1:7305 — it is `{provider, model, engine, host, host_by, source, in_roster, unresolved}`), so codex coordinators classify `other`; map the coordinator's provider *name* to a vendor class instead (F02-6). Host is noise for weighting; include only if nearly free, never display it.

## Q4. Unknown models
- (a) family patterns: private aliases can share a family prefix; pattern-list growth is unbounded and mis-extraction leaks.
- (b) raw id + k-anonymity: fails before the threshold — the label leaves the machine at send time and the regex matches private aliases (F02-2).
- (c) PR allow list: safest; residual failure is maintainer error and slow coverage; the PR itself publicly links a model name to this project.
- (d) nothing: no privacy failure; fails the ask.
Recommend (c), or the unlisted consent flag (option 3).

## Q5. Order of work
Decide before either half: judge-field shape and its rate-time provenance (v2 additive, hard to change later); the unknown-model privacy rule; and re-rate semantics — telemetry emits one event per rating while the local store keeps only the latest (F02-4, confirmed), so the site must dedupe by consultation or counts inflate. Changeable later without contract break: coefficients, k, minimum n, tier values, paging UI — all site-side.
